# AI Product Lab

AIが自動でプロダクトを作って改善する実験のダッシュボード。

1. AIがアイデアを出す → 人が採用を承認
2. AIがLP（紹介ページ）の文章を作る → 人が公開を承認
3. LPで事前登録を集める（今は公開・広告出稿は手動。シミュレーションでも試せる）
4. 訪問数か広告費が基準に達すると、AIが「続ける・改善・撤退」を提案 → 人が承認
5. 終わった案件からAIが教訓を書き、次のアイデア出しで参照する

「AIの使い分け」画面では、各工程をどのAIに任せるか決めるために、複数社のモデルに同じ問題を解かせて正答率・ブレ・費用を比べる。

主なファイル: `src/lib/loop.ts`（製品ループ）、`src/lib/ai.ts`（予算・緊急停止つきのAI呼び出し）、`src/lib/demo.ts`（AIを使わないデモ案件）。

## 起動

```bash
npm install
cp .env.example .env.local   # 実APIを使うときだけキーを書く
npm run dev -- -p 3456
```

http://localhost:3456 を開く。キーがなくても「ダミー」モードで画面と集計の動作を確認できる。

## 構成

| 場所 | 内容 |
|---|---|
| `src/lib/models.ts` | 比較するモデルと料金（OpenAI・Gemini は要確認の参考値） |
| `src/data/*.json` | 問題データ（作成者 `author` を記録して偏りを検証する） |
| `src/lib/tasks.ts` | プロンプト（シンプル／詳細 × 日本語／英語）と採点 |
| `src/lib/providers.ts` | 各社APIの呼び出しとダミー実行 |
| `src/lib/runner.ts` | 見積もり・予算チェック・実行・緊急停止 |
| `src/lib/stats.ts` | 正答率（95%信頼区間）・一致率・コスパの集計 |
| `data/ai-lab.db` | 実行結果（SQLite、git管理外） |

## ガードレール

- 実APIの実行前に費用を見積もり、月間予算を超える実行は開始しない
- 実行中に予算上限へ達したら自動で停止
- 緊急停止ボタンで実行中の処理もすべて止める
- Claude の拒否時に別モデルへ切り替える fallbacks は、比較を公平にするため使っていない（拒否はエラーとして記録）
