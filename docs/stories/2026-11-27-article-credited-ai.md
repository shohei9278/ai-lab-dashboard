# 人が指示に書いた物差しを、記事ではAIの気づきとして書いていた

- 日付: 2026-11-27
- 関わるもの: zenn-articles の note の下書き `note/2026-11-27-x-night.md`（zenn-articles #5・#8・#9）、話の種 `2026-11-26-ai-moves-promo-to-x.md`、ai-lab の `src/lib/plan.ts`

## 起きたこと
- 11/27 の朝、記事の下書きのルーティンが、話の種 `2026-11-26-ai-moves-promo-to-x.md` から note の下書き「訪問の多い場所を捨てて、使われる場所を選んだAI」を書いた
- 運営者が「実験に沿いすぎていて、普通の人は興味がないと思う」と言い、Claude Code が、読む人の困りごとを主役にする形に書き直した（#8）。本文には「3つの数を並べて渡しただけで、AIは使われた数のほうを見た」と書き、頼み文には「来た人の数ではなく、使ってくれた人の数で比べて」と入れた
- 運営者が「そう頼んだら、使われた数で選ぶのは当たり前じゃない？」と言った
- Claude Code が朝会の指示（`src/lib/plan.ts`）を読むと、「宣伝先の配分は、訪問の平均ではなく、直近14日の利用数と利用率で決める」は、11/23 に指示に書き足した決まりだった。11/25 には、運営者の判断で、費用を1成果あたりで比べるようにもしていた。「AIが自分で使われた数を見た」は誤りだった
- 「人が物差しを決めて、AIが毎朝数え直した」話に書き直した（#9）。運営者は「内容はよくなったが、種がよくないのかも。使った人を優先するのは、普通の人として当たり前」と言った

## AIに渡していた指示・人が先に決めていたこと
- 記事の下書きのルーティンへの指示（zenn-articles の `docs/routine-article-draft.md`）には、AIへの指示を読んで確かめる決まりがなかった。材料は、話の種・PR・改善の記録・本番の画面
- 話の種の書き方（`docs/stories/README.md`）にも、AIに渡していた指示を書く欄がなかった

## 思ったのと違った所
- 話の種の「人がしたこと」に「なし（朝会はAIだけで決めた）」と書いてあった。当日の朝会では、人は何もしていない。ただし物差しは、人が先に指示に書いていた。その欄を、記事を書いたAI（ルーティンと Claude Code）がそのまま信じた
- 読む人の困りごとを主役にしても、芯にした「見られた数より使われた数を見る」が宣伝の常識だったので、記事が当たり前になった
- この話でAIと仕事をして分かったことは、別の所にあった。11/23 に物差しを足しても、前から指示に残っていた2行（1訪問あたりの費用だけを渡す・週3件の上限）がそのままで、11/25 にそろえるまで X は少ないままだった（改善の記録 `post-mix.json`）。上限は X の件数を直接抑えていた。費用の見方がどれだけ効いたかは、実行記録で確かめていない

## 人がしたこと・言ったこと
- 運営者が、記事を読んで、上の3つのことを言った（実験に沿いすぎ・頼み文で答えを言えば当たり前・使った人を優先するのは常識）
- 運営者が、読む人はエンジニアや、ITを勉強している人でよいと言った（AIに興味のある人はエンジニアが多いため）。そのうえで、Zenn との切り分けが要ると言った
- 運営者が、記事を選ぶ基準は「記事全体を通して、ためになる部分があるか」でよいかと聞いた。Claude Code が、「明日1つ変えられることを1文で書けるか」「それが常識でなく、AIと仕事をして初めて分かったことか」の2つに分けると伝え、運営者が直すと決めた（改善の記録 `story-seed-gate.json`）

## どうなったか
- 話の種の書き方に、「AIに渡していた指示・人が先に決めていたこと」「思ったのと違った所」「AIと仕事をして分かった、明日変えられること」の欄を足した
- `2026-11-26-ai-moves-promo-to-x.md` に、人が先に決めていた物差しを書き足した
- 記事の下書きのルーティンにも、同じ2つの関門と、AIの気づきとして書く前に指示を読む決まりを足した（zenn-articles #10。11/27 にマージ）。11/27 の下書きも、「プロンプトに決まりを足したのに、2日間効かなかった」に書き直した（同じ PR）

## まだ分からないこと
- 2つの関門で、ルーティンが選ぶ話が、読まれる記事になるか
- 欄がないと、AIは人の決めた物差しをAIの判断として書く、と言えるのは今回の1件から。ほかの場面でも同じになるかは確かめていない

- 読む人: AIで開発しているエンジニア
