# マージしたのに本番に出なかった。原因は、テストのブラウザの版だった

- 日付: 2026-11-26
- 関わるもの: PR #194・#195・#198、Railway、GitHub Actions の CI、自動の戻し（auto-revert）

## 起きたこと
- 10:46 に PR #194（提案の幅を広げる変更）を main にマージした。Railway への反映が約4分で failure になった
- 運営者が Railway の画面を見ると「CI check suite failed」。Railway は main の CI が通った版だけを出す設定で、main の CI の Chrome を使うテスト6件が落ちていた（`Check failed: has_site_`）。同じ中身の PR の CI は10分前に通っていた
- CI の落ちたジョブをやり直すと通ったが、Railway は自分では出し直さなかった。運営者が Railway で出し直しても、約1分で failure になった
- 本番の確認（30分ごと）は「main の最新が本番に出ているか」も見ていて、2回続けて失敗すると、自動の戻しがそのマージを元に戻す。12:00 ごろまでに出さないと #194 が戻される見込みだった
- 小さな PR #195（#194 の ai-review で残した指摘の直し）を作って先にマージし、新しい版として出し直した。11:34 ごろに本番に出て、#194 の中身も一緒に出た。自動の戻しは動かなかった

## 意外だった所・ぶつかった所
- コードの不具合ではなく、テストが使うブラウザの版が原因だった。テストは、パソコンに入っている Google Chrome を先に使っていて、GitHub 側で更新された Chrome の新しい版が、隔離した枠（sandbox 付きの iframe に srcdoc）で落ちていた
- 同じ日の PR #197 の CI でも同じ6件が落ち、たまたまではないと分かった
- 直した PR #198 の最初の CI も落ちた。CI の手順で、ブラウザを入れる段階がテストのあとにあり、テストの段階では Playwright の Chromium がまだなかった

## 人がしたこと・言ったこと
- 運営者が Railway の画面の文（「CI check suite failed」）を貼り、Railway で出し直した
- 運営者が「小さな PR で出し直す」と決め、#195 の ai-review の指摘は「先にマージ」して次の PR で直すと決めた
- 運営者が、CI の Chrome のテストを直すと決めた

## どうなったか
- PR #198 で、ブラウザは Playwright に付いてくる Chromium（版が決まっている）を先に使い、CI はテストの前にブラウザを入れるようにした。そのあとの CI は Chrome のテストも含めて通っている（11/26）

## まだ分からないこと
- CI で Playwright の Chromium が開けないと、黙って Google Chrome に切り替わる作りは残っている（PR #198 の ai-review の指摘。直していない）
