# 話の種（note の記事の材料）

運営者が書く note の記事は、1本に1つの話（テーマ）にする（運営者が決めた）。
その材料になりそうな出来事を、ここに1件1ファイルで貯める。記事の下書きを書くルーティン（zenn-articles の `docs/routine-article-draft.md`）が毎朝読み、いちばん面白い話を1つ選んで書く。

## 貯めるとき
- ai-lab の作業（Claude Code とのやり取り）で、話になりそうな出来事があったら、その作業の PR に1ファイル足す（決まりは `CLAUDE.md`）
- ファイル名: `docs/stories/YYYY-MM-DD-<英小文字とハイフン>.md`（出来事の日付。日本時間）
- 話になりそうな出来事の目安（どれか1つに当たればよい）
  - AI が、数字や結果を見て、自分で判断を変えた
  - AI の仕組みが、思わぬ所で止まった・間違えた。そして人がどう直したか
  - AI どうしで意見が割れた・AI と人の判断が違った
  - 数字がはっきり動いた（良くても悪くても）
  - 人の出番がはっきり変わった（人がしていたことを AI に任せた・任せていたことを人に戻した）
- 小さな直しの一覧や、仕組みの説明だけのものは種にしない（それは PR と改善の記録で足りる）

## 書き方（事実だけ・短く）
```markdown
# 題（その話を一言で）

- 日付: 2026-11-26
- 関わるもの: PR #194・#195、本番の「毎日の計画」など

## 起きたこと
（何が起きたか。時刻・数字は記録にあるものだけ）

## 意外だった所・ぶつかった所
（なぜ話になるのか。AI がどう考えて動いたか）

## 人がしたこと・言ったこと
（運営者が実際に言ったこと・決めたことだけ。言っていない判断は書かない）

## どうなったか
（結果。数字は日付つき。まだ分からなければ、そう書く）

## まだ分からないこと
```
- 感想・気持ちは書かない（記事では【】で空けて、運営者が書く）
- 秘密の値・個人の情報・来訪者に見せていない下書きや AI の入出力は書かない。運営者の名前は書かず「運営者」と書く
- 記事に使われたかは、記事の下書き（zenn-articles の `note/`）の先頭のコメントの「使った話の種」でわかる。ここのファイルは消さない
