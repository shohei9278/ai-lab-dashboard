# AIが作れるものの縛りを見直す（設計）

11/28 に運営者が、「ブラウザで動く小さなツール」という縛りは嫌なので、縛りを全部見直したいと言い、まず設計の文書から書くと決めた。
この文書は、何をどの順で広げるか、広げても何を守るかを決めるためのもの。作るのは、ここで決めたあとに1段ずつ別の PR で行う。

## これまでの経緯
- 11/17 に、「じっくり案件」の第1段（大きなデータ・人が入れる素材・見た目を磨く段）を作った。第2段（外部の API を許す）は、AIがどんな API をどれだけ欲しがるか分からないので、入口だけ作った（`src/lib/apiWishes.ts`。AIが書いた「使いたい API」を数える）

- 同じものが何度も欲しがられたら、AIが使えるサービスを調べ、定例会議で運営者に契約を頼めるようにした（`src/lib/wants.ts`）。契約したあと、ツールからつなぐ部分（共有の保存・外部の API の中継）は、運営者が後回しにしていた
- 11/28 から、Claude Code につながっているときは、ツールは全部じっくり案件として、クラウドの Claude Code がブラウザで確かめながら作る

## 広げても変えないこと
- 秘密の値（API キー・トークン）は、ツールにも、ツールのコードにも、ブラウザにも渡さない。Vercel・Railway の変数にだけ置く
- ツールの枠は隔離したままにする。allow-same-origin は付けない。CSP で外への通信を広く開けない
- 訪問者の情報を、外に送るときは、送り先と送るものをプライバシーポリシーに書いてから送る。運営者が承認していない送り先には送らない
- お金がかかるものは、サーバーの側で1日の上限と1人の回数を決め、緊急停止（`killSwitch`）と月の予算（`monthlyBudgetJpy`）で止まるようにする
- 訪問・利用・シェアの数え方は、どの出し方でも、今と比べられる形にする
- AIだけで公開できる範囲は、新しい仕組みごとに決める。決めるまでは、新しい仕組みを使うツールは人の承認に回す

## 共通の作り: 窓口を足す
①〜③ は、どれも同じ作りで足す。ツールが外と直接やり取りするのではなく、今の `window.labStore` と同じように、ページの側の窓口にお願いし、Hitoride のサーバー（Vercel）が代わりに行う。

```
ツール（隔離された枠） --postMessage--> ページ（ToolFrame） --> Hitoride のサーバー（/api/tool-…） --> Supabase・外部の API・AI
```

- ツールの CSP は今のまま（通信できないまま）にできる。鍵は Hitoride のサーバーにだけある
- 窓口は、案件ごとに「使ってよい」と決めたものだけ開く。使える窓口の一覧は、ページとサーバーの両方が見る
  - 一覧は、ツールを作る流れ（AI・ルーティン・`/api/tool-jobs`）からは変えられない。人の承認（または決めたチェック）の処理だけが決め、承認した公開の版に結び付けて置く
  - ツールの中身を変える権限と、窓口を許す権限は分ける。ツールを直して新しい版になったら、前の版の許可は引き継がず、もう一度承認する
- 機械のチェック（`staticToolIssues`）は、今の禁止の項目（通信・外部のファイル・保存領域・Cookie・`alert`・`window.open`・送信するフォーム など）をそのまま残し、「使ってよいと決めた窓口以外を使っていないか」を足す（`alert`・`window.open` などは CSP では止められないので、置き換えない）
- 窓口を作るときに、`needs.ts` のその種類の `ready` を true にし、ツールを作るときの決まり（`toolRules`）も一緒に直す（`needs.ts` の注に書いてあるとおり）
- 呼び出しの確かめは、ページとサーバーの両方で行う
  - ページ（ToolFrame）は、知らせの送り元が、そのツールの枠であることを確かめてから、サーバーに頼む（今の `labStore` と同じ）
  - サーバーは、ページを通さない直接の呼び出しも来る前提にする。ツールの番号と版は誰でも分かるので、それが合うだけでは通さない。呼び出しのたびに、公開中の今の版か（`/api/event` と同じ確かめ方）・その案件に許した操作か・入力の形と長さ・回数とお金の上限を確かめる

## ① みんなで共有する保存
- できること: 投票・みんなの結果の割合・ランキング・「あなたは○人目」
- 作り: `window.labShared`（仮の名前）。Supabase に、ツールごとの数を数える表を足す
- 最初は、数と、決めた選択肢だけを保存する。訪問者が書いた自由な文は保存しない（ほかの人に見えると、荒らしや個人情報が出る）
  - 自由な文を見せたくなったら、別の段で決める（AI の確かめ・通報・消す手立てが要る）
- 何度も入れられないよう、訪問者の番号（今の `visitorId`）ごとに回数を決める。番号はブラウザごとなので、数えられるのは1ブラウザあたりの回数（別のブラウザを使えば増やせる）。数が小さいうちは、少ない数の割合を大きく見せない
- プライバシーポリシーに、ツールで選んだものを保存することを書く

## ② 外部の API
- できること: 天気・地図・祝日・翻訳など
- 作り: `window.labApi`（仮の名前）。運営者が承認した API の一覧を持ち、Hitoride のサーバーが代わりに呼ぶ。ツールは一覧の名前と決めた引数だけを渡せる
- 一覧の1件ごとに、呼ぶ先・送ってよい引数・鍵の変数の名前・1日の回数・結果をためておく時間・送る情報を書く。鍵の値は書かない
- 最初は、鍵が要らず、訪問者の情報を送らない API から始める
- どれを一覧に入れるかは、`apiWishes.ts` が数えた「使いたい API」の多い順を材料に、運営者が決める
- 送り先ができるので、プライバシーポリシーに API ごとの送り先と送るものを書く

## ③ その場で AI を呼ぶ
- できること: 訪問者の入力に AI が答える・名前を付ける・診断の文を書く・絵を描く
- 作り: `window.labAi`（仮の名前）。Hitoride のサーバーが AI を呼ぶ
- AIへの指示（どう答えるか）は、ツールのコードに書かせず、案件ごとに決めて、公開の前に人かチェックが確かめたものに固定する。固定した指示は、窓口の許可と同じく、承認した公開の版に結び付け、サーバーはその版の指示だけを使う。指示を変えたら、新しい版として承認し直す。ツールから渡せるのは、訪問者の入力（長さの上限あり）と決めた選択肢だけにする
- お金の上限: 全体の1日の上限（円）・1ブラウザの1日の回数・1回の長さを決める。上限に届いたら、ツールは「今日はここまで」と出し、AI なしで遊べる作りにさせる。月の予算と緊急停止でも止まる
  - 同時に呼ばれても上限を超えないよう、AI を呼ぶ前に、1回にかかりうる最大の額（サーバーが付ける固定の AI への指示を含めた、AI の会社に送る入力の全部と、答えの長さの上限から出す）を、1日と月の残りから先に取っておく（取るのと残りを確かめるのを、1回の DB の操作で行う）。終わったら実際の額で精算し、余りを戻す。取れなければ呼ばない
  - 時間切れなどで答えを受け取れず、お金がかかったか分からないときは、余りを戻さず、取っておいた最大の額を使ったものとして扱う。あとで使った量を確かめられたら、そのときに精算する
  - AI の会社への呼び出しは、自動でやり直さない（SDK のやり直しも切る）。やり直すときは、1回ごとに、呼ぶ前に最大の額を取り直す
- 出てきた文が、ほかの人に見せられない内容になっていないかを確かめてから返す
- 訪問者の入力と AI の答えは、最初は保存しない（数と費用だけ数える）。直すために読みたくなったら、別の段で決める
  - 「保存しない」は、DB に入れないことに加えて、Hitoride のサーバーのログ（エラーのログを含む）にも本文を出さないこと
  - AI の会社の側で入力と答えが残るか・どれだけの期間残るかは、公開の前に確かめ、プライバシーポリシーに書く
- 結果の画面に、AI が書いたものだと分かる一言を出す
- AI に送ることを、プライバシーポリシーに書く

## ④ 出し方を足す
今の LP とツールのほかの出し方。重いものほど人の作業が増え、AI だけで回る部分が減る。

| 出し方 | 人の作業 | 数え方 | 重さ |
| --- | --- | --- | --- |
| ホームに置けるアプリ（PWA） | ほぼなし。Hitoride に置き方を足すだけ | 今と同じ（Web） | 軽い |
| 画像・動画そのものを作品にする | 投稿は今と同じ | SNS の数 | 軽い〜中 |
| Discord・LINE の bot | アカウント作り・審査・鍵の用意 | bot の側で作り直す | 中 |
| Chrome 拡張・スマホのアプリ | ストアの登録・審査・料金 | ストアの数を手で入れる | 重い |

- 最初は PWA を足す。印刷物と SNS のアカウント型も入れやすい（下の「運営者が決めたこと」にほかの候補と一緒に書いた）。ほかは、AI が会議でそれを欲しがったら（`wants.ts` の欲しい仕組みとして数える）、運営者が決める
- アイデアの形（kind）を増やすのは、出し方を1つ足すときに一緒に行う（kind を先に増やすと、作れない案が出る）

## ⑤ 大きさ
- HTML の断片1つ・長さの上限は、①〜④を入れるときに、足りなくなったぶんだけ広げる。先には変えない

## 運営者が決めたこと（11/28）
Claude Code のおすすめを、運営者が「おすすめの通りで」と決めた。
- 順番は、上の「順番」のとおり
- ③ の上限
  - 全体で1日100円（毎日上限まで使っても、月に最大3,100円（31日の月）。月の予算1万円の約3割）
  - 1人1日10回まで。訪問者はログインしないので、数えられるのはブラウザの単位で、実際は1ブラウザあたり1日10回（別のブラウザを使えば増やせる）。全体の1日の枠を、少ない人が使い切らないようにする手立ては、③ を作るときに別に決める
  - モデルは Claude Haiku 5.5（100万トークンあたり入力 0.10ドル・出力 0.50ドル）。1回を入力1,000・出力300トークンとすると約0.04円（1ドル150円）で、100円で約2,600回
  - 絵を描くのは Claude ではできず、別の画像を作るサービスが要り、1枚数円と費用の桁が違う。最初は文だけにし、絵は別の段で決める
- ③ を使うツールは、最初は人の承認に回す（AI だけでは公開しない）
- ① で、自由な文は最初は見せない
  - 自由な文が要るのは、大喜利（お題に答えて投票）・寄せ書き・みんなが付けた名前の案を並べる・匿名の悩みに答える、などの案
  - 文がなくても、投票・ランキング・「あなたは○人目」・みんなの結果の割合は作れる。決まった言葉を組み合わせて選ばせる形と、本人が自分の SNS でシェアする形（今の `labShare`。保存しない）も使える
  - 自由な文が要る案を AI が何度も欲しがったら（`wants.ts` で数える）、AI の確かめ・通報・運営者が消せる手立てをそろえて、次の段に進む
- ④ の候補に、次を足す。PWA と並べて、印刷物と SNS のアカウント型を入れやすいものとする
  - 印刷して使うもの（塗り絵・ワークシート・ビンゴカードの PDF など）: ツールの枠は今もファイルを保存させられる（`allow-downloads`）ので、一番軽い
  - SNS のアカウントそのものを作品にする（毎日お題を出す・診断を返す など）: 今の自動投稿の仕組みを広げる
  - 毎日届くもの（メールや LINE で毎日のひとこと・クイズ）: 「戻ってくる」ねらいに合う。送る仕組みは新しく要る
  - AI を使う人向けの道具（Claude のスキル・MCP など）: 個人開発の人がそのまま客になる
  - LINE スタンプ・壁紙: 売れるが、ストアの審査と販売の手続きが要る
