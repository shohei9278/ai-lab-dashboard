# ダッシュボードをサーバーに置く（PCを閉じていても動かす・ポートフォリオとして公開する）

今はPCの中で動いているダッシュボードを、Railway のサーバーに移します。GitHub のリポジトリと連携するので、移したあとは `git push` するだけでサーバーに反映されます。

移すと、次のようになります。

- PCを閉じていても、毎朝の計画・5分ごとの取り込み・SNSへの投稿・判断・週の定例会議が動く
- `https://〇〇.up.railway.app` を、だれでも**閲覧だけ**できる（ポートフォリオとして見せられる）
  - ボタンは見えるが、押すと「公開中のデモでは押せません」と出る。操作はサーバー側で全部断る
  - 連絡先・SNSのコメントの相手と本文・他人の投稿の本文・利用者が書いた声・デザインの参考の画面・エラーの詳細は「デモ表示」で伏せる
- あなたは `/login` でパスワードを入れると、今までどおり全部の操作ができる（30日ログインのまま）
- データ（案件・費用の記録・画面の写真など）は、サーバーのボリューム（保存領域）に置く
- ツールの自動テストやページの画面の確認も、サーバーで動く（Chromium と日本語のフォントを入れてある）

費用の目安は月$5〜10です（Hobby プラン）。所要時間は30〜40分ほどです。

## 1. Railway のアカウント

1. ブラウザで GitHub を開き、右上のアカウントが **リポジトリの持ち主のアカウント**（`ai-lab-dashboard` があるアカウント）になっているか確かめる。別のアカウントでログインしていたら、先に切り替える
2. https://railway.com で「Login with GitHub」から登録し、**Hobby プラン**にする

## 2. GitHub のリポジトリからプロジェクトを作る

1. Railway の画面で **New Project → Deploy from GitHub repo** を選ぶ
2. 初めてのときは、Railway の GitHub アプリを入れる画面が出る。**Only select repositories** で `ai-lab-dashboard` だけを選んで許可する（ほかのリポジトリは見せない）
3. `ai-lab-dashboard` を選ぶ。リポジトリの一番上にある `Dockerfile` を見つけて、自動で組み立てが始まる
   - 初回は10分ほどかかる（Chromium と日本語のフォントを入れるため）
   - この時点ではキーやボリュームがないので、うまく動かなくて大丈夫

キー（`.env.local`）とデータ（`data/`）は、GitHub にも Railway にも送られません（`.gitignore` と `.dockerignore` で除外しています）。

## 3. Railway の管理画面での設定

できたサービスを開いて、次を設定します。

**ボリューム（データの保存領域）**
- サービスを右クリック（またはコマンドパレット）→ **Volume を追加**、マウント先は `/data`

**Settings**
- **Source**: ブランチが `main` になっているか確かめる（`main` に push すると自動で反映される）
- **Region**: 日本に近いもの（Asia の Singapore など）
- **Networking → Generate Domain** で `https://〇〇.up.railway.app` を作り、控える

**Usage Limits（使用量の上限）**
- 想定外の請求を防ぐため、上限を設定しておく（例: $15）

**Variables**（キーは `.env.local` と同じ値を入れる。チャットや GitHub には貼らないでください）

| 名前 | 値 |
|---|---|
| `DASHBOARD_PASSWORD` | 運営者のログイン用のパスワード（20文字以上のランダムなもの。パスワード管理アプリで作るのがおすすめ）。**これを入れると、来た人は閲覧だけになります** |
| `ANTHROPIC_API_KEY` | `.env.local` と同じ（Webで調べる機能もこのキーを使う） |
| `OPENAI_API_KEY` | `.env.local` と同じ |
| `GEMINI_API_KEY` | `.env.local` と同じ |
| `SUPABASE_URL` | `.env.local` と同じ |
| `SUPABASE_SERVICE_ROLE_KEY` | `.env.local` と同じ |
| `X_API_KEY` / `X_API_SECRET` / `X_ACCESS_TOKEN` / `X_ACCESS_SECRET` | `.env.local` と同じ |
| `THREADS_ACCESS_TOKEN` | `.env.local` と同じ |
| `BLUESKY_HANDLE` / `BLUESKY_APP_PASSWORD` | `.env.local` と同じ |
| `NOTIFY_WEBHOOK_URL` | `.env.local` と同じ |

`AI_LAB_DB`（`/data/ai-lab.db`）と `TZ`（`Asia/Tokyo`）は `Dockerfile` で決めてあるので、入れなくて大丈夫です。

入れ終わると自動で組み立て直されます。`https://〇〇.up.railway.app` を開いて、上に「公開中のデモです」と出れば閲覧の側はOKです。`/login` で上のパスワードを入れて、その帯が消えれば運営者の側もOKです（この時点ではデータは空です）。

## 4. 今のデータをサーバーに移す

1. **PCのダッシュボードを止める**（移している間にデータが変わらないようにするため。Claude に頼めば止めます。AIが作業中でないことを確かめてから止めます）
2. `ai-lab` のフォルダで次を実行し、聞かれたら `DASHBOARD_PASSWORD` を入力する（入力は画面に表示されません）

```bash
npx tsx scripts/push-db.mts https://〇〇.up.railway.app
```

3. 「DBを移しました」「画面の写真などのファイルを N件送りました」「完了しました」と出たら、サーバーのダッシュボードを開いて、案件や画面の写真が並んでいるか確かめる

サーバーにすでに実案件があるときは、上書きしないよう止まります。わざと上書きするときだけ、最後に `--force` を付けてください。

## 5. PCの側を止める

サーバーとPCの両方で自動実行が動かないよう、PCの `.env.local` に次の1行を足します。

```
AI_LAB_SCHEDULER=off
```

これ以降は、サーバーのダッシュボードを使ってください。PCのダッシュボードを開いても古いデータのままなので、承認などはサーバーの方で行います。

## 6. 動作確認（Claude に「サーバーの動作確認して」と伝えてください）

- ログインせずに開いて、ボタンが押せないこと・伏せるべきものが伏せてあること
- ログインして、ホーム・判断待ち・設定が開けること、設定に「✓ Supabase に接続済み」が出ること
- 5分ほど待って、処理ログに取り込みの記録が出ること
- 翌朝、今日の計画が作られること

## コードを変えたあと

`main` に push すると、Railway が自動で組み立てて差し替えます（5〜10分ほど）。データはボリュームにあるので、差し替えても消えません。

```bash
git push
```

- **push する前に、サーバーのダッシュボードの右下に「AIが作業中」が出ていないか確かめる**。差し替えるときにサーバーが再起動するので、AIがページやツールを作っている途中だと、その作業は止まります（Claude が push するときは、確かめてから送ります）
- 文書だけの変更でも、push すると組み立て直されます
- 差し替えたあとにおかしくなったら、Railway の **Deployments** で1つ前のデプロイを選び、**Redeploy** で戻せます
- 自動で反映させたくないときは、Settings で自動デプロイを切ると、画面の **Deploy** を押したときだけ反映されます

## 注意

- パスワードを知っている人は、承認やAIの呼び出し（お金がかかる操作）ができます。パスワードは人に教えないでください
- リポジトリは公開なので、キーやパスワードは GitHub に置かず、Railway の Variables にだけ入れてください
- 来た人に見せたくないものが新しく増えたときは、Claude に「デモ表示で伏せて」と伝えてください
- 公開用のLPサイト（`lp-site`、Vercel）は、これとは別のサービスです。LPサイトを変えたときは、今までどおり Vercel にデプロイします
